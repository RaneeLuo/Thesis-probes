# 分节写作与交接规则

**状态：用户于 2026-09-21 确认最终大纲，并计划每个 section 一个聊天，完成后整合进 Overleaf。**

本文件规定共同写作方式；进度单独记录在 [SECTION_STATUS.md](SECTION_STATUS.md)。本次上下文更新没有创建新聊天，也没有更改 Overleaf。

## 1. 每个新聊天先读什么

1. [PROJECT_CONTEXT.md](../PROJECT_CONTEXT.md) 中的“Accepted thesis-writing basis — 2026-09-21”，包括本轮五项事实纠正。
2. [最终大纲易读版](thesis_skeleton_v3_merged_readable_zh.md)，了解全篇主线和当前 section 的职责。
3. [最终合并大纲](thesis_skeleton_v3_merged.md) 中对应小节及其证据核对要求。
4. [SECTION_STATUS.md](SECTION_STATUS.md) 中该节的现有记录、相邻节接口和已完成材料。
5. 该节需要的规范结果文件、事实台账、必要代码或文献，以及当前正文。旧正文是可复用材料，不能仅因早先写过而当成新版已经完成。

结构与章节编号以 2026-09-21 最终版为准。实验事实仍需要来源支持；大纲最终确认不等于每个数字和统计表述都重新核验完毕。

## 2. 一个聊天负责多大的范围

开始时记录 section 编号、标题、写作目的、预计页数、材料位置和边界。例如“4.2 RQ1”包含设计、主要发现、检查与解释、RQ 答案；若用户只指定“4.2.1”，就只负责其设计部分。

不自行改正式 RQ 原文、全篇贡献、其他 section 或共同判决定义。需要跨节调整时，在交接说明中写出具体位置和原因；获得相应任务授权后再改。

已有布局无需每次重新请求确认。当前会话的新指令优先，真实的新变更记录日期和范围。

## 3. 写作步骤

1. **明确本节任务。** 用几句中文说清读者读完应理解什么；知道哪些背景已由前文负责。
2. **准备事实依据。** 涉及实验时，核对主要比较、有效样本范围、结果与限制；可沿用有来源和版本记录的核验。遇到缺失内容，继续完成不依赖它的部分，并单独列出待核对项。
3. **写英文正文。** 使用英式拼写，围绕研究问题组织，数字进表、正文解释。必要实验细节留在正文，完整执行材料归附录。
4. **检查本节。** 检查数字、分析范围、引用、术语、标签、与相邻节的重复和过渡。不能把近机会当作等价，或把未检出依赖当成不存在依赖。
5. **交付与交接。** 给出正文/LaTeX、中文修改说明、证据记录、未解决事项及所用版本。依据用户当次授权进行 Overleaf 整合；已有明确授权时不重复请求相同确认。

没有新的事实疑点时，不为重新写一句话而重跑实验。需要补算时先明确缺少的量和所属分析范围；不得借用其他群体的区间。

## 4. 全篇共用的边界

- 三个主要研究对象是 CLaSP、TRACE、ChatTS；文本嵌入模型是阴性对照；未训练 CLaSP 是另一个指标对照。
- CLaSP 三个训练 checkpoint、TRACE 同一 checkpoint 的三次掩码抽样、ChatTS 两种答案顺序必须区分。
- 各 RQ 使用“设计 → 主要发现 → 有效性检查与解释 → 回答”；只写其中一个小节的聊天也要了解这条完整逻辑。
- 第 3.4 节集中定义共同指标与判决词汇；各 RQ 解释自己的具体比较，不另造定义。
- 第 4.5 节汇总三个 RQ 下的模型表现；第 5 章讨论整个研究的意义。两处不重复结果表。
- 跨模型比较限于明确条件下的行为与判定，不能凭原始或相对分数给不同接口和数据的模型排名。
- 保留全部查询、顺序依赖查询和认证题集的区别。涉及主要结论的数字记录指标、n、CI/其他不确定性、重复单位及结果文件字段。
- 不把大纲简写直接升级成内部机制或创新首创的结论；参考范文只影响写作结构，不引入其项目知识。

## 5. 每节留下哪些文件和状态

可采用 `docs/thesis_sections/section_4_2/` 这样的独立目录；这里只规定命名方式，不表示目录内已经有稿件。仅在开始该节时创建。

- `section.tex`：对应 section 的 LaTeX 正文。
- `evidence.md`：支撑主张的文件/字段或文献、分析范围、核对版本及必要解释。
- `handoff.md`：本节任务、主要修改、相邻节交叉引用、未解决事项、用户认可的具体版本、Overleaf 对应位置和最后一次核对记录。

在 SECTION_STATUS 中分开记录：
- **已写**：有实际稿件，并可定位版本。
- **已核对**：注明已核对的范围与剩余问题，不笼统写全部正确。
- **用户认可**：只有对应版本得到用户明确认可时才记录；这是一项记录，不新增重复审批要求。
- **已放入 Overleaf**：只有实际写入并确认对应位置后才记录；编译检查结果另列。

几种状态不能互相代替。已有旧版正文是否可复用，需要读取后确定；“未登记”不表示用户从未写过这一节。

## 6. 整合到 Overleaf 时

按照用户授权，将完成的指定 section 写入目标论文项目。写入前读取该位置的当前内容，并核对是否有其他聊天或用户的新改动。保存需要替换的原文或利用可核验版本，避免覆盖较新的编辑。

按节逐次整合；多个聊天可以各自写草稿，同一个 Overleaf 文件中的修改应依次完成。若本节位于共享章节文件，只替换本节范围。

检查交叉引用、引用文献和图表；编译后检查错误、缺失引用及实际篇幅。未能编译或未确认写入的情况如实记录，不能仅根据本地文本声称 Overleaf 已完成。
